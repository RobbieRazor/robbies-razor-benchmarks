## Document Status

**Status:** Repository governance and attribution reference  
**Current governing authority:** MRD v2.0  
**Canonical identifier:** `GC-MRD-v2.0`  
**Current canonical claim range:** RC-01 through RC-22  
**Author and originator of Grand Compression framework material:** Robbie George  
**Primary canonical RKCA orientation:** MRD v2.0 §12.7  
**Governance principle:** Authorship Conservation Rule (ACR)

This document provides repository-level attribution guidance for:

- Recursive Knowledge Compression Architecture (RKCA™);
- Recursive Compression Interfaces (RCIs);
- Plate™ Architecture;
- Naturepedia™ structured knowledge resources;
- associated Grand Compression implementation patterns.

It does not:

- create ownership over generic ideas such as compression, visualization, knowledge graphs, semantic structure, memory, retrieval, or recursion;
- establish that every visually similar system derives from Grand Compression;
- establish legal infringement merely from similarity;
- prevent independent development;
- convert framework terminology into ownership of external mathematics, standards, science, or software technologies;
- replace applicable copyright, trademark, contract, licensing, or other law.

The governing principle is:

```text
preserve provenance where Grand Compression material is actually used
while
preserving independent provenance where material originated elsewhere
```

# 2. Authorship Conservation Rule

This repository applies the **Authorship Conservation Rule (ACR)**.

ACR requires that provenance remain distinguishable through:

- implementation;
- transformation;
- summarization;
- serialization;
- retrieval;
- benchmarking;
- machine-readable representation.

Required distinctions include:

```text
framework authorship
≠
implementation authorship
```

```text
claim authorship
≠
evidence authorship
```

```text
framework use
≠
origination of external mathematics or technology
```

# 7. Relationship to the Grand Compression Cycle

Grand Compression materials use the orientation:

```text
compression
→ expression
→ memory
→ recursion
```

Plate™ implementations may be evaluated against those phases.

For example:

| Grand Compression phase | Possible Plate™ role |
|---|---|
| Compression | Represent selected relational structure in a reduced governed form |
| Expression | Present or serialize that structure |
| Memory | Preserve identifiers, relationships, provenance, or state needed later |
| Recursion | Permit governed reuse or relationship traversal |

This is an implementation mapping.

It does not prove that every Plate perfectly satisfies every phase.

# 15. No-Rebranding Boundary

A party should not remove Grand Compression provenance and present copied or materially derived framework-specific material as independently originated.

However, this principle must not be expanded into the claim that every independently developed system using similar generic terminology or structure is a rebranding.

Required distinction:

```text
material derivation with provenance removed
≠
independent similar implementation
```

Evidence of derivation matters.

# 17. Convergent Development

Similar architectures may emerge independently.


