## How to Interpret These Files

Architecture files may have one of the following roles.

### Canonical-Section Mirror

A repository-accessible rendering or implementation-oriented summary of material governed by a specific MRD section.

The underlying MRD section is canonical. The repository copy does not become an independent source of authority.

### Derived Architecture Note

An engineering interpretation that explains how canonical principles may apply to a bounded technical or operational problem.

Derived notes must remain consistent with the MRD and must not silently introduce new canonical claims.

### Diagram or Orientation Document

A visual or condensed representation designed to make the architecture easier to understand.

Diagrams are explanatory interfaces. They must not be treated as complete definitions or empirical evidence.

### Research or Evaluation Model

A model intended for benchmarking, diagnosis, or falsifiable evaluation.

Research models must declare their variables, scope, scale, baseline, evidence status, limitations, and failure conditions.

## Core Architectural Cycle

The primary orientation cycle is:

```text
compression → expression → memory → recursion
```

Architecture documents should preserve the distinction among:

- compression of structure
- expression of preserved structure
- durable memory
- recursive reuse
- prediction
- action
- feedback
- recompression

Repeated processing alone does not establish stable recursion. Identity, relationships, provenance, constraints, version state, and retrieval paths must remain sufficiently preserved for the declared purpose.

## Plate-to-Mesh Implementation Architecture

The primary Naturepedia implementation sequence is:

```text
Plate™ → Registry → System Map → Knowledge Mesh
```

This sequence implements progressively connected knowledge layers while preserving:

- identity
- relationships
