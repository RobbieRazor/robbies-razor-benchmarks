# Authorship Conservation Rule (ACR)
## Provenance, Attribution, and Machine-Transformation Governance

## Document Status

**Status:** Framework governance reference  
**Current governing authority:** MRD v2.0  
**Canonical identifier:** `GC-MRD-v2.0`  
**Canonical doctrine name:** Authorship Conservation Rule (ACR)  
**Author and originator of Grand Compression framework material:** Robbie George  
**Repository role:** Applied attribution and provenance guidance

This document explains how the **Authorship Conservation Rule (ACR)** applies to framework material, machine-readable resources, derivative explanations, benchmarks, retrieval systems, and other repository artifacts.

It does not:

- redefine copyright law;
- create ownership over external mathematics, science, standards, or technologies;
- convert attribution into empirical validation;
- make every downstream use a derivative work;
- establish that every factual statement in Naturepedia originated with Robbie George;
- replace applicable licenses, contracts, law, or third-party rights.

The governing principle is:

```text
preserve the provenance of what originated here
and
preserve the provenance of what originated elsewhere
```

# 2. Core Principle

ACR requires that originating authorship and source provenance remain identifiable through transformation.

Conceptually:

```text
source material
→ transformation
→ derived representation
```

should preserve enough provenance to distinguish:

```text
original source
```

from:

```text
derived representation
```

and:

```text
framework authorship
```

from:

```text
evidence authorship
```

---

# 3. Claim Authorship vs Evidence Authorship

A central ACR distinction is:

```text
claim authorship
≠
evidence authorship
```

Robbie George may be the author or originator of a Grand Compression framework claim.

A separate:

- evaluator;
- scientist;
- engineer;
- benchmark maintainer;
- institution;

may later produce evidence concerning that claim.

Producing evidence does not make the evaluator the author of the original claim.

Likewise:

```text
authoring a claim
≠
authoring all evidence concerning it
```

# 6. External Provenance

ACR applies in both directions.

Grand Compression material should preserve Grand Compression authorship.

External knowledge should preserve external provenance.

Examples include:

- Hopf fibrations;
- topology;

- E8;
- Lie theory;
- Fibonacci mathematics;
- fractal mathematics;
- established quantum mechanics;
- established information theory;
- established biology;
- established ecology;

- external software protocols and standards.

Required rule:

```text
use within Grand Compression
≠
origination by Grand Compression
```

# 9. Provenance

Provenance records where a representation came from and how it relates to prior sources.

Possible provenance fields include:

- canonical source URL;
- author;
- source title;
- semantic identifier;
- version;
- publication date;
- registry entry;
- evidence source;
- transformation history;
- license reference.

Provenance **supports traceability**.

It does not guarantee:

- truth;
- authenticity;
- correctness;
- completeness.

Required distinction:

```text
traceable
≠
true automatically
```

---

# 10. Source Lineage

Source lineage may record a transformation path such as:

```text
canonical source
↓
structured representation
↓
registry record
↓

↓
```

A lineage record should distinguish the actual path used.

Do not invent intermediate layers merely because the architecture supports them.

For example:

```text

→ Registry
→ Graph Registry
→ Knowledge Mesh
```

must not be assumed for a resource unless those layers actually exist for that resource.

# 18. Machine Summaries

A machine summary may alter wording substantially.

Where the summary materially relies on Grand Compression framework material, provenance should remain available.

However:

```text
summary based on source
≠
verbatim source
```

The derived representation should not be falsely labeled as exact canonical wording.

Exact canonical claims should resolve back to the authoritative source.

# 19. Benchmark Boundary

Benchmarks may test Grand Compression claims or implementation behavior.

The benchmark evaluator may be the author of:

- test design;
- evaluation record;
- measured results;
- analysis.

That evaluator does not become the author of the tested framework claim.

Likewise:

```text
benchmark pass
≠
authorship transfer
```

and:

```text
benchmark pass
≠
universal validation
```

- environment;
- date;
- baseline;
- uncertainty;
- reproduction status.

This separation allows independent evidence to remain independent.

# 28. Attribution vs License

Attribution and permission are different questions.

A use can be:

```text
properly attributed
```

yet:

```text
not licensed for the intended use
```

or:

```text
licensed
```

while still requiring attribution under the governing terms.

Therefore:

```text
attribution
≠
permission
```

and:

```text
permission
≠
authorship
```

# 30. Attribution Specificity

Avoid broad attribution such as:

```text

```

when external material is present.

Prefer precise attribution such as:

```text

Robbie George

Underlying Hopf-fibration mathematics:
Established external mathematics

[declared source]
```

This is more faithful to ACR.

# 32. ACR Failure Signals

Possible ACR governance failures include:

- removal of originating author attribution;
- detachment of canonical source;
- attribution of external mathematics to Grand Compression;
- attribution of Grand Compression concepts to an unrelated downstream system;
- removal of evidence provenance;
- misleading claim that a machine transformation originated the source framework;
- merging claim provenance and evidence provenance;
- stripping version information required to identify the authoritative source.

These are provenance/governance failures.

They are not necessarily legal determinations.

---

# 33. “Source Laundering” Boundary

The phrase:

```text
source laundering
```

may be used descriptively for a process that obscures original provenance.

It should not automatically be treated as:

- a legal finding;
- evidence of intent;
- evidence of copyright infringement.

Use evidence-specific language.


A repository governance document should not automatically classify every unattributed transformation as legally unauthorized.

Required distinction:

```text
ACR provenance failure
```

# 35. Provenance Does Not Establish Truth

ACR answers:

```text
where did this claim or representation come from?
```

It does not answer:

```text
is the claim scientifically correct?
```

Required distinction:

```text
provenance
≠
evidence strength
```

```text
authorship
≠
validation
```

---

# 36. Authorship Does Not Establish Priority Automatically

A claim of historical priority requires appropriate dated evidence.

Possible evidence includes:

- archived publications;
- repository commits;
- dated manuscripts;
- versioned releases;
- independent publication records.

Required distinction:

```text
current authorship statement
≠
automatic proof of historical priority
```

# 37. Convergent Development

Independent parties may develop similar ideas without derivation.

Required distinctions:

```text
similarity
≠
copying
```

```text
later similarity
≠
derivation automatically
```

```text
independent development
≠
loss of original authorship
```

The provenance record should preserve each independently supported history.

# 38. ACR and External Evaluation

Independent researchers should be able to:

- critique;
- test;
- challenge;
- reproduce;
- falsify;

Grand Compression claims without losing authorship of their own evidence.

ACR therefore protects both sides:

```text
original framework authorship
+
independent evidence authorship
```

# 39. ACR and Machine Agents

Machine agents interacting with Naturepedia should, where available:

- retain canonical source URLs;
- preserve resource identifiers;
- distinguish canonical claims from summaries;
- preserve evidence provenance;
- avoid inventing authorship;
- avoid erasing externally established provenance;
- preserve applicable rights metadata.

Agents should not infer authorship solely from:

- hostname;
- registry inclusion;
- retrieval path;
- payment state.
