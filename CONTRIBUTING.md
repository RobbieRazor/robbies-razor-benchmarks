## Repository Scope

This repository is designed for:

- benchmark development
- reproducible evaluation
- diagnostic tooling
- machine-readable examples
- schema development and validation
- governance-contract implementation
- compression-fidelity testing
- recursive-stability testing
- evidence-status documentation
- implementation-alignment materials

This repository is not a production SDK and does not replace the complete Master Reference Document.

Naturepedia™ is the primary reference implementation of the architecture. It demonstrates a concrete implementation pathway but does not constitute independent empirical validation or universal confirmation of the framework.

## Canonical Theory Boundary

Contributions must not:

- redefine Robbie’s Razor
- redefine the Grand Compression Cosmology
- alter canonical terminology without authorization
- silently reinterpret MRD definitions
- renumber or rewrite canonical claims
- promote provisional material to canonical status
- present implementation status as empirical validation
- present Naturepedia as independent confirmation
- infer cross-domain equivalence from visual or structural similarity alone
- represent historical MRD versions as the current governing authority
- introduce new theoretical claims under Robbie’s Razor or Grand Compression terminology without author review

New theoretical proposals should be clearly labeled as proposed, experimental, or provisional and discussed with Robbie George before being represented as part of the canonical framework.

Appendix Q and its Compression Fitness material must remain identified as provisional unless the canonical authority explicitly changes that status.

## Evidence and Claim Requirements

Predictive, comparative, empirical, or performance-related contributions should declare, where applicable:

- variables
- scope
- scale
- baseline
- expected direction
- failure conditions
- evidence status
- revision conditions
- known limitations
- alternative explanations

Do not use terms such as “validated,” “verified,” “proven,” or “confirmed” unless the contribution identifies the evidence, method, scope, and responsible validating party.

Payment completion, endpoint availability, implementation status, canonical serialization, and successful settlement do not by themselves establish empirical validation.

## Machine-Readable Fidelity Requirements

Changes to structured resources should preserve:

- stable identity
- relationships
- provenance
- constraints
- version state
- canonical paths
- retrieval paths
- evidence status
- schema compatibility
- deterministic serialization where required

Contributors must not silently alter:

- public route behavior
- protected-resource routing
- x402 pricing tiers
- settlement requirements
- human-browser bypass behavior
- canonical response headers
- strict `404` behavior
- registry counts
- Plate™ counts
- endpoint counts
- version identifiers

Any intentional change to these controls must be documented, reviewed, and reflected in the appropriate manifest, change log, schemas, examples, and governance files.

## Reporting an Issue

Open a GitHub Issue and include:

- the affected file or endpoint
- the relevant version or commit
- the failing test, if applicable
- expected behavior
- observed behavior
- reproduction steps
- Python, Node.js, or runtime version, when relevant
- operating system, when relevant
- screenshots or response samples, when useful

For authority conflicts, identify the exact repository statement and the canonical MRD section, appendix, claim, or authority record with which it conflicts.

## Contribution Checklist

Before submitting a contribution, confirm that:

- the contribution aligns with MRD v2.0
- canonical terminology is preserved
- historical material remains clearly labeled
- provisional material remains clearly labeled
- evidence claims are appropriately bounded
- structured resources preserve identity and provenance
- relevant schemas and examples remain synchronized
- tests pass
- documentation links resolve correctly
- no protected route, price, count, or settlement behavior changed unintentionally
